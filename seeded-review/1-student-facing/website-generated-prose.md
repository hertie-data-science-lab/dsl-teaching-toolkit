# Course website prose (student- and public-facing)

The site is a **three-layer stack** and only one layer is editable from this repo.

| Layer | Repo | Owns |
| --- | --- | --- |
| Theme | `hertie-data-science-lab/dsl-jekyll-theme` | layouts, schedule table + column headers, row colours, Updates box, footer, nav rendering |
| Template | `hertie-data-science-lab/course-website-template` | `_config.yml` defaults, the home page body, `_images/` |
| **This repo** (`dsl_course/site.py`) | — | **the data and the tabs**: 5 `_config.yml` values, `_data/nav.yml`, the five tab pages, `_lectures/`, `_assignments/`, `_events/`, `_data/people.yml`, `_data/materials.yml`, `_publish-config.yml`, `public-materials/` |

**Edit the strings in section 1 below.** Section 2 is recorded so you can see the whole
student-visible surface, but changing it needs a PR to the other two repos - tell me which
ones matter and I'll note them as follow-ups.

---

## 1. Editable here - generated by `dsl_course/site.py`

### 1.1 Tab pages and nav labels
The sync writes the tab bar and each tab's page, so the labels and the one-line note under
each heading are ours:

| Tab | Cohort site note | Public site note |
| --- | --- | --- |
| Home | *(template's own page)* | *(same)* |
| Schedule | *(no page - driven by the rows below)* | *(same)* |
| Lectures | Lecture slides are only accessible to enrolled students. | Lecture slides by session. |
| Labs | Lab materials are only accessible to enrolled students. | Lab materials by session. |
| Readings | Citation lists are public; the files themselves are accessible to enrolled students. | Readings by session. |
| Assignments | Assignments are only accessible to enrolled students. | Assignments by hand-out date. |
| All Materials | Every course material released to this cohort, session or not. Course materials are only accessible to enrolled students. | All materials released |
| Materials | *(cohort only)* | Readings by session. |

The public site drops Readings and All Materials, and keeps `/materials/` as its readings
page under the label **Materials**.

`_data/nav.yml` header:
```
# Generated by `python3 -m dsl_course.site sync`. Rewritten on every sync - add a
# page of your own as a file in the repo and link it from `index.md` instead.
```

### 1.2 Session / lab rows
```
Session {N}                                    # row title, lectures
Lab {N}                                        # row title, labs
```
A **released** row has no body at all - the links are on the row and the tab page already
says who can open them. Its `subtitle:` and `description:` are the session's `title:` and
`description:` from `schedule.yml`.

An **unreleased** row (planned, nothing shipped) keeps its subtitle and description, flags
`unreleased: true`, and reads:
```
Materials for session {n} are not released yet - they will appear in {repo links} when released.
```
(The `- they will appear in …` clause is dropped when the plan names no destination.)

A row whose plan ships readings, where no readings section has landed yet, also flags
`readings_pending: true`.

### 1.3 Assignment page
Not yet handed out - the brief is withheld, the row and its dates stay, `unreleased: true`:
```
{Slug Title Cased}                             # title from the slug, NOT the README
This assignment has not been handed out yet. Its brief appears here, and your private `{slug}-<your-handle>` repo in `{course_org}`'s cohort org, when it does.
```
Handed out - title and body come from the assignment README's first `# ` heading and the
rest of the file, with this line appended:
```
Assignment brief.                              # body fallback when the README has none
_Your private `{slug}-<your-handle>` repo in `{course_org}`'s cohort org appears once the teaching team provisions it._
```

### 1.4 Exam and event rows
```
Details to be confirmed.                       # exam body -> "Course Material" column
MidTerm Exam                                   # synthesised stub, week 8
Final Exam                                     # synthesised stub, end of term
Term starts
Term ends
```
Untitled events are title-cased from their slug: `project-clinic` -> `Project Clinic`.

### 1.5 Download link names
```
{singular-section} - {filename}                # e.g. "lecture - 01_slides.pdf"
```
> **Load-bearing across repos - change with care.** The theme and template filter on these
> exact prefixes (`lecture -`, `lab -`, `reading -`) to decide which page a file appears
> on. A release landing at a repo *root* produces `content-f2026 - slides.pdf`, which shows
> on the schedule row but **not** on the Lectures/Labs/Materials pages. Known footgun -
> say if you want it fixed.

### 1.6 Reading lists
A session's readings folder produces prose **and** a file list, never one instead of the
other. `READINGS.md` (or `.txt`/`.bib`) is the optional prose overlay and is inlined into
the row's `reading_list:`; every other file in the folder is a normal download link. On the
cohort site the files are links, so only the overlay is inlined; on the public site in
`reading-list` mode nothing is hosted, so the files are listed by name under the prose.

No prose of ours here - the overlay is faculty-written (its seeded stub is
`materials-repo/readings/01_session-1/READINGS.md`) and the heading above it is the theme's.

### 1.7 `_data/people.yml` header
```
# GENERATED by the DSL course sync - do not edit this file. Every sync rewrites
# it and your change is lost. Edit {edit_at} instead.
# These cards are {note}.
```
`{note}` is either ``declared in the `people:` block`` or
`auto-generated from the org's instructors team`. Fallback card when no people are
declared: `Course staff`.

### 1.8 Public course site only
```
Materials for {title}.                         # row body - no "enrolled students only" gate
Open Courseware                                # replaces the semester label
```

### 1.9 `_publish-config.yml` header
```
# Written by `python3 -m dsl_course.site public-sync` - the settings of the
# last publish. The daily 'Publish course website' cron re-syncs from them;
# delete this file to stop the automatic refresh.
```

### 1.10 Site-repo overwrite notice (a GitHub issue, not a page)
Title: `Manual edits to generated site files are overwritten by the sync`, with a prose
body explaining which parts regenerate. Filed in the site repo when a human edit is
detected. Full text in `2-faculty-facing/notifications.md`.

## 2. NOT editable here - theme and template

### Theme repo (`dsl-jekyll-theme`)
- Home headings: `Course Description`, `Previous Offerings`, `Instructors`, `Teaching Assistants`
- Updates box: `Updates`, `New Lecture is up: …`, `New Lab is up: …`, `New Assignment released: …`
- Schedule table headers: `Event` | `Date` | `Description` | `Course Material`
- Row labels + colours: `Lecture` (red), `Lab` (green), `Assignment out` / `Assignment due ⚠` (blue), `Exam` (grey), special events (brown), `Term` (purple)
- Assignment page: `Released on …`, `Due Date: …`, `Download …`, `Late Policy`, `No assignments released yet.`
- The `tl;dr:` label and the reading-list heading; footer `Hertie School Data Science Lab`

> There is **no empty-state message** anywhere in the stack - the Updates box is simply
> suppressed when nothing is released. If you want a "no materials released yet" line,
> that's a theme change.

### Template repo (`course-website-template`)
- `index.md`: `Welcome to **{{ site.course_name }}** at the [Hertie School Data Science Lab](…).` and the `**Questions?**` line

### Template placeholders the sync never replaces
These show template defaults on every live site until a human edits the site repo:

| Key | Stale default |
| --- | --- |
| `project.md` body | `Describe Final project.` |
| `_data/late_policy.yml` | three `8 late days` bullets |
| `schoolname` / `schoolurl` / `address:` | `Hertie School`, Friedrichstraße 180 block |
| `dateformat` | `%m/%d/%Y` (US order) |

> The first two are visibly wrong on any live cohort site. Worth deciding whether the sync
> should own them.

### Placeholders the sync DOES replace
`course_name` (`Course Name (Code)`), `course_description`, `course_semester`
(`Fall 2025`), `course_code`, `github_org`, and the `Instructor Name` / `TA Name` /
`placeholder.jpg` cards.
