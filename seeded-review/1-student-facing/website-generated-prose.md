# Course website prose (student- and public-facing)

Every human-readable string the sync puts on a course website, split by which site owns it
and by page. Two sites are generated from this repo:

- the **cohort site** (`<cohort-org>.github.io`) - what an enrolled student reads;
- the **public open-courseware site** (`<course-org>.github.io`) - optional, multi-year,
  no cohort behind it.

## What changed since the last round: almost all of this is now editable here

The site is a **two-layer** stack, not three, and the layer this repo owns has grown to
cover nearly everything a student sees:

| Layer | Where it lives | Owns |
| --- | --- | --- |
| Generic chrome | `hertie-data-science-lab/dsl-jekyll-theme`, pinned at `e4b8fdc9e87b4729c9dcef142591551a2361d4b5` (its **v2.0.0**) | header, footer, nav *rendering*, brand colours, the `default` / `page` / `post` layouts |
| **This repo** | `templates/site/` (SYSTEM-OWNED, rewritten every sync) | the eight course layouts, the thirteen includes, `_sass/_course.scss` - **every heading, column header, row label, empty-state line, button and row colour listed below** |
| **This repo** | `templates/site-seed/` (INSTRUCTOR-OWNED, seeded once) | `index.md`, `schedule.md`, `_config.yml`, `_data/late_policy.yml`, `_data/previous_offering.yml`, `Gemfile`, `.gitignore` - rendered copies under `site-repo/` beside this file |
| **This repo** | `dsl_course/site.py`, `site_repo.py`, `public_site.py` | the DATA and its prose: `_config.yml` values, `_data/nav.yml`, the tab pages, `_lectures/`, `_assignments/`, `_events/`, `_data/people.yml`, `_data/materials.yml`, `_publish-config.yml`, the site repo's own `README.md` |

There is **no `course-website-template` repo any more**: `scaffold_site` creates
`<org>.github.io` empty with only its Pages build, and every sync writes `templates/site/`
over it and seeds `templates/site-seed/` into any path the site lacks.

**Everything in sections 1-4 is editable here.** Only section 5 needs a PR elsewhere.

## 1. The cohort site

### 1.1 Tab bar and tab pages

`_data/nav.yml` and the tab pages are written from ONE table (`site_repo._THEME_PAGES`), so
a tab can never point at a page the site lacks. Nav order is the table's order.

| # | Nav label | URL | Page file | The page's whole body |
| --- | --- | --- | --- | --- |
| 1 | Home | `/` | `index.md` *(instructor-owned - see `site-repo/index.md`)* | |
| 2 | Schedule | `/schedule/` | `schedule.md` *(instructor-owned, empty - the table is generated)* | |
| 3 | Lectures | `/lectures/` | `lectures.md` | Lecture slides are only accessible to enrolled students & auditors. |
| 4 | Labs | `/labs/` | `labs.md` | Lab materials are only accessible to enrolled students & auditors. |
| 5 | Readings | `/readings/` | `readings.md` | Hosted files are only accessible to enrolled students & auditors. |
| 6 | Assignments | `/assignments/` | `assignments.md` | Assignments repos are only accessible to enrolled students. |
| 7 | All Materials | `/materials/` | `materials.md` | All released course material so far; only accessible to enrolled students/auditors. |

Each generated tab page is exactly:
```
---
layout: lectures
title: Lectures
permalink: /lectures/
---

Lecture slides are only accessible to enrolled students & auditors.
```

`_data/nav.yml` header:
```
# Generated by `python3 -m dsl_course.site sync`. Rewritten on every sync - add a
# page of your own as a file in the repo and link it from `index.md` instead.
```

### 1.2 The ownership stamp on every generated collection page

Inserted as the first line INSIDE the front matter (Jekyll needs `---` on line 1), at the
write site, so no renderer can ship an unstamped page:
```
# SYSTEM-OWNED - do not edit. Generated by the DSL course sync, which clears and
# rewrites this whole collection on every run. Edit the source instead: the cohort's
# classroom-config/schedule.yml (dates, titles) or its org structure (what released).
```

### 1.3 Schedule rows

`schedule.yml` has three blocks and each encodes behaviour: `releases:` deploys materials,
`assignments:` carries a handout/due/grading lifecycle, `events:` is display-only. Rows come
out of them like this - one `_includes/schedule_row_*.html` per type, dispatched by an
explicit `case` branch (a filename built from `event.type` would fail the WHOLE build the
first time a schedule carried an unknown type; an unknown type falls through to a plain row
instead).

| schedule.yml | Row `type:` | Col-1 label | Row colour | Label colour |
| --- | --- | --- | --- | --- |
| `releases:` (any section but `labs`) | `lecture` | **Lecture** | `#f2dede` red | `#a94442` |
| `releases:` (`labs` section) | `lab` | **Lab** | `#dff0d8` green | `#3c763d` |
| `assignments:` (the entry) | `assignment` | **Assignment out** | `#d9edf7` blue | `#31708f` |
| `assignments:` (its `due_event`) | `due` | **Assignment due** | `#d9edf7` blue | `#31708f` |
| `events:` `type: exam` | `exam` | **Exam** | `#f0f1f2` grey | `#5a5f66` |
| `events:` (default) | `special_event` | **Event** | `#fbf2d5` amber | `#7d6230` |
| `semester_start:` / `_end:` | `term_date` | **Term starts** / **Term ends** (fallback **Term**) | `#e5dcf0` violet | `#59468f` |
| anything unrecognised | *(as written)* | the raw `type`, or **Event** | none | none |

All seven backgrounds sit at the same pale tonal level so body text and links keep >5:1
contrast, and each label clears 4.5:1 on its own row. Bold is reserved for the col-1 label -
no other column in a schedule row is bolded.

Row titles:
```
Session {n}                       # lecture row title
Lab {n}                           # lab row title
```
`subtitle:` is the session's declared name (the identifier stays and the name sits under it,
because the identifier is what ties the row to `materials/lectures/03_...`). `description:`
is the session's learning objectives. Both are **kept on an unreleased row**, so the whole
term reads as a syllabus from day one rather than a list of empty rows that fills in weekly.

A **released** lecture/lab row has **no body at all** - the links are on the row and the tab
page already says who can open them. *(The old "Materials for session 1. Open the links
above (you must be an enrolled member of ...)" line is gone from the cohort site; it
survives, shortened, only on the public site - see 2.3.)*

An **unreleased** row (planned, nothing shipped) flags `unreleased: true` and reads:
```
_**Materials for session 3 are not yet released** - they will appear in [`materials/lectures/03_intro`](…) when they are._
```
The `- they will appear in …` clause is dropped when the plan names no destination. Each
destination is a link when its repo exists, plain `` `repo/path` `` when it does not.

A row whose plan ships readings, where no readings section has landed, also flags
`readings_pending: true`. That produces, on the Readings tab only and only when the session
is not wholly unreleased:
```
Readings for this session are not yet released.
```

`show_on_site: false` on a release entry produces **no prose of its own**: it suppresses the
row, the row's date and the row's name, while still contributing its destination paths and
its `readings_planned` flag to a row that exists for another reason.

Exam rows carry one body line, on every exam row, TBC or not:
```
Details to be confirmed.
```
Two exam rows are synthesised when the schedule declares none: **MidTerm Exam** (term start
+ 8 weeks) and **Final Exam** (term end).

Untitled special events are title-cased from their slug: `clinic-drop-in` -> **Clinic Drop
In**. A special event's name goes in `description:` (the Title column), never in `name:` -
put in `name:` it landed where "Lecture"/"Lab"/"Exam" print a row's KIND and left the Title
cell empty.

Every row's Date cell prints the date, the time, and the weekday name; `TBC` replaces the
date on a `dateless:` row and `(TBC)` follows it on a `tbc:` one.

### 1.4 The assignment page

Not yet handed out - the brief is withheld, the row and its dates stay, `handout_pending:
true`:
```
Assignment 1                      # title from the SLUG, title-cased, never the README
_**Assignment 1 is not yet released** - your private `assignment-1-<your-handle>` repo appears when it is._
```
(Group assignments say `assignment-4-project-<your-team>`.) Deliberately word for word the
shape of an unreleased session's line - they render in the same column and on adjacent tabs,
so they read as one status vocabulary.

Handed out - the body is the template README with its `# ` heading lines stripped, fenced in
`{% raw %}`. The fallback when the README has nothing but a heading:
```
Assignment brief.
```
Plus, from the layout:
```
Released on Thursday 01/10/2026          # or: Hands out on Thursday 01/10/2026
Due Date: 15/10/2026 23:59
Open your private submission repo on GitHub          # button
Your work goes in `assignment-1-<your-handle>`. Clone it, commit as you go, and push to `main` - that push is your submission.
Late Policy                                          # heading above _data/late_policy.yml
Submit by pushing to `main` in `assignment-1-<your-handle>`.   # repeated under the brief
```
`repo_url` is the cohort org's repo list filtered to this assignment, not one student's
address: the page is public and identical for everyone, and GitHub shows a signed-in student
only the repos they can see, so the filter lands on their own.

The due row's Details column says where to submit:
```
Submit via `assignment-1-<your-handle>`
```

> The layout also has a `Download [problems] [attachment] [solutions]` block and an
> `Files / problems (pdf) / attachments (zip)` block on the Assignments index. Both read
> hand-authored front matter (`pdf`, `attachment`, `solutions`) that this sync never writes,
> so on a generated site they are dead. Say if you want them removed.

### 1.5 Download link names

```
{singular-section} - {filename}          # e.g. "lecture - 01_slides.pdf"
lecture - browse the folder              # the escape hatch when the list is narrowed
lecture - handouts/ (3 files)            # a folder link in the default shape
```
`_singular` strips one trailing `s`, so a free-form section name survives: `lectures` ->
`lecture`, `readings` -> `reading`, `faq` -> `faq`. Empty case is the literal `links: []`.

> **The prefix is stripped on some pages and not others.** The Lectures / Labs / Readings
> tabs remove it, so a student reads `01_slides.pdf`. The schedule's Details column and the
> Updates box do NOT, so the same file reads `lecture - 01_slides.pdf` there, with a
> `Download lecture - 01_slides.pdf` tooltip. One file, two names. Flag if you want that
> settled one way.

### 1.6 Reading lists

A session's readings folder produces prose **and** a file list, never one instead of the
other. `READINGS.md` (or `.markdown` / `.txt` / `.bib`, matched on the whole filename) is the
optional prose overlay; its own headings are demoted two levels so `## Required Readings`
nests under the session heading instead of outranking it. Every other file in the folder is
a normal download link.

On the cohort site only the overlay is inlined - the files are real links beside it, so
naming them again would say it twice. No prose of ours here: the overlay is faculty-written
(its seeded stub is `materials-repo/readings/01_session-1/READINGS.md`) and the heading above
it comes from the session block.

### 1.7 `_data/people.yml`

```
# GENERATED by the DSL course sync - do not edit this file. Every sync rewrites
# it and your change is lost. Edit hertie-dsl-demo-f2026/classroom-config/people.yml instead.
# These cards are declared in the `people:` block.
```
The third line is either ``declared in the `people:` block`` or `auto-generated from the
org's instructors team`. Fallback featured card when nobody is declared at all: **`Course
staff`**.

### 1.8 `_data/materials.yml` (the All Materials index)

```
# Generated by `python3 -m dsl_course.site sync` - every released file, nested
# as its repo has it. Edit nothing here; it is rewritten on every sync.
```
Directory rows carry a file count, rendered as `— 12 files` / `— 1 file`; nested nodes as
`(3 files)` / `(1 file)`.

### 1.9 `_config.yml`

Two halves. **Course identity, replace-only** - a key the file lacks is a no-op:

| Key | Value |
| --- | --- |
| `course_name` | the course org's `dsl-course.yml` name |
| `course_semester` | `Fall 2026` / `Spring 2027`, from the cohort's term tag |
| `course_code` | the `dsl-course.yml` code |
| `course_description` | the `dsl-course.yml` description, folded to one line |
| `github_org` | the **cohort** org - never the course org |

**Template contract, upserted whether or not the file has the key**, each preceded by
```
# managed by the DSL course sync - rewritten on every run
```

| Key | Value |
| --- | --- |
| `title` | the course name under Jekyll's own spelling (a site with neither this nor `course_name` fails the build outright) |
| `remote_theme` | `hertie-data-science-lab/dsl-jekyll-theme@e4b8fdc9e87b4729c9dcef142591551a2361d4b5` |
| `dateformat` | `%d/%m/%Y` |
| `collections` | `events` / `lectures` / `assignments` output true, `announcements` false |
| `defaults` | `layout: "assignment"` for the assignments collection |

And the seed template's own header line is rewritten to name what the sync owns:
```
# Edit the fields below for your course - EXCEPT the course-identity keys the DSL
# course sync owns and rewrites on every run: `collections`, `course_code`, `course_description`, `course_name`, `course_semester`, `dateformat`, `defaults`, `github_org`, `remote_theme`, `title`.
# Change those in the course org's .github/dsl-course.yml instead.
```

### 1.10 The site repo's own `README.md`

Faculty-facing but seeded into a PUBLIC repo, so it is here. Opens:
```
<!-- SYSTEM-OWNED - do not edit. Generated and redeployed by the DSL course sync. -->

# hertie-dsl-demo-f2026 - auto-deployed course website

**Do not edit this repository.** It is machine-written: every sync rewrites the generated
files below and pushing redeploys the site, so an edit here is overwritten and lost.

Its content comes from the cohort's `classroom-config/` files (`schedule.yml`, `people.yml`)
and what the course org actually releases.
```
then a "What the sync owns" table (`_lectures/`, `_assignments/`, `_events/`,
`_data/people.yml`, `_data/nav.yml`, `_data/materials.yml`, the five tab pages, `_layouts/`
+ `_includes/` + `_sass/_course.scss`, `deploy.yml`, `_config.yml`), an "Everything else is
yours" section naming `index.md`, `schedule.md`, `_announcements/`, `_images/`, `Gemfile`,
`.gitignore` and the two `_data` files, and:
```
The rendering is not yours to change here: `_layouts/`, `_includes/` and `_sass/_course.scss`
are shipped from `templates/site/` in the DSL teaching toolkit, and the rest of the styling
from the shared `dsl-jekyll-theme`. An edit in this repo is overwritten on the next sync;
open a PR against the toolkit instead, and every course site gets it.

If you edit a generated file anyway, the sync opens an issue naming the commit it overwrote,
so the change can be copied back out of it.
```

### 1.11 The overwrite notice (a GitHub issue, not a page)

Title:
```
Manual edits to generated site files are overwritten by the sync
```
Filed in the site repo after a push that replaced a human-authored commit, one bullet per
overwritten file naming its author and the commit. Full body in
`2-faculty-facing/notifications.md`.

## 2. The public open-courseware site - differences only

Everything in section 1 applies unless listed here.

### 2.1 The tab bar loses two tabs and renames a third

| Nav label | URL | Page file | Layout | The page's whole body |
| --- | --- | --- | --- | --- |
| Home | `/` | `index.md` | `home` | *(the same seeded page - see `site-repo/index.md`)* |
| Schedule | `/schedule/` | `schedule.md` | `schedule` | |
| Lectures | `/lectures/` | `lectures.md` | `lectures` | Lecture slides by session. |
| Labs | `/labs/` | `labs.md` | `labs` | Lab materials by session. |
| Assignments | `/assignments/` | `assignments.md` | `assignments` | Assignments by hand-out date. |
| Materials | `/materials/` | `materials.md` | `readings` | Readings by session. |

**Readings** and **All Materials** are not generated at all. `/materials/` keeps its original
meaning here: it IS the readings page, under the label **Materials**, so the nav label for
the same permalink differs between the two sites.

> **`Assignments by hand-out date.` is never actually shown.** The public plan clears
> `_assignments` outright, and the layout short-circuits an empty collection, so the public
> Assignments tab renders only `No assignments yet.` on every course. Either the note is
> dead text or the tab should not be generated - worth a decision.

### 2.2 Course identity

- `course_semester` is the constant **`Open Courseware`** rather than a term label - the
  site is multi-year. It renders beside the course name on the home page.
- `github_org` is the **course** org, not a cohort. It is the footer's only click-back and
  what `index.md`'s **Questions?** link resolves to.
- `course_description` is **not** written on this site.
- No `_data/materials.yml`, no `_events/`, no `_assignments/`, no `subtitle:` or
  `description:` on a session row.
- `_data/people.yml` is instructors only (`teaching_assistants: []` always) - TAs are
  declared per cohort, and this site outlives cohorts. Its header points at ``the `people:`
  block of <course-org>/.github/dsl-course.yml``.

### 2.3 The one string only this site has

```
Materials for session 3.                 # session row body - no "enrolled students only" gate
Materials for lab 3.
```
This is the sentence the cohort site deleted; it survives here because there is no gate to
explain and no unreleased state.

### 2.4 Readings, three modes

- `reading-list` (**the default**) hosts nothing: the page carries the overlay's prose
  followed by the other files' **raw filenames as plain text**, no links. Raw filenames
  deliberately - deriving "Blitzstein 2019 ch.1" from `blitzstein-ch1.pdf` would be
  inventing a citation.
- `actual-readings` copies and serves the files, which then appear as ordinary
  `reading - <file>` links.
- `none` publishes nothing.

`.releaseignore` is consulted **only on this path**, and only to suppress: in
`reading-list` mode nothing is copied, so without the check a withheld reading was named on
the open web and a withheld overlay had its full text published there. It contributes no
string of its own. The cohort site is not `.releaseignore`-aware at all.

### 2.5 `_publish-config.yml`

```
# Written by `python3 -m dsl_course.site public-sync` - the settings of the
# last publish. The daily 'Publish course website' cron re-syncs from them;
# delete this file to stop the automatic refresh.
source_repo: course-materials-f2026
readings_mode: reading-list
include_lectures: true
```

Published files live under `public-materials/<source-repo>/session-<n>/<section>/…`.

## 3. Editable here - the vendored layouts and includes

All of this ships from `templates/site/`, is rewritten on every sync, and reaches every
course site the moment it merges. Every file carries the first line:
`SYSTEM-OWNED - do not edit. Written by the DSL course sync from templates/site/ in the
toolkit; every sync rewrites it.`

### 3.1 Headings and column headers

| Where | Text |
| --- | --- |
| Home | `Syllabus` (pinned link, only when a syllabus has been released), `Course Description`, `Previous Offerings`, `Instructors`, `Teaching Assistants` |
| Home, course line | `{course_name} / {course_semester}` |
| Schedule | page title `Schedule`; column headers `Event`, `Date`, `Title`, `Details` - rendered **uppercase** by the stylesheet |
| Schedule, narrow screens | the same four words reappear as per-cell labels (`data-label`) |
| Session blocks (Lectures / Labs / Readings) | heading `Session 3 - Probability theory`, then the description, then `Files` above the link list |
| All Materials | a section's `— 12 files` / `— 1 file` count; nested `(3 files)` |
| Assignment page | `Late Policy` |
| Home, Previous Offerings | each item is bulleted with a `●` glyph from the stylesheet |

### 3.2 Empty states

| Page | Text |
| --- | --- |
| Lectures | `No lecture materials released yet.` |
| Labs | `No lab materials released yet.` |
| Readings | `No readings released yet.` |
| Assignments | `No assignments yet.` |
| All Materials | `Nothing has been released to this cohort yet.` |
| Home / Updates box | *(none - the box is suppressed when nothing is released)* |

A session with no reading list, no reading files and no pending readings does not appear on
the Readings tab at all - a lecture-only week would otherwise sit there reading "not
released yet" for the whole term.

### 3.3 The Updates box

Heading `Updates`, seven newest entries, and one of:
```
New Lecture is up: Session 3 [lecture - 01_slides.pdf]
New Lab is up: Lab 3 [lab - 01_worksheet.ipynb]
New Assignment released: [Assignment 1]
```
plus, for a hand-written `_announcements/` entry, its own text. Exams, special events and
term dates are deliberately excluded - they are not news, and several carry no text to show.

### 3.4 Seeded once, instructor-owned - rendered copies under `site-repo/`

| File | What a student reads |
| --- | --- |
| `site-repo/index.md` | the landing page's `Welcome to **{course_name}** at the Hertie School Data Science Lab.` and the `**Questions?**` line. The one page of the site whose words are the instructor's - and the same file on both sites |
| `site-repo/schedule.md` | front matter only; anything an instructor writes here appears above the generated table |
| `site-repo/_data/late_policy.yml` | the three late-day bullets, shown on **every** assignment page |
| `site-repo/_data/previous_offering.yml` | seeded as an empty list, so the home page's Previous Offerings block shows nothing until an instructor fills it |

The `_config.yml` seed also carries `Hertie School`, the Friedrichstraße 180 address block
and the DSL org URL. It is seeded once and never rewritten except for the keys in 1.9 - so
these are now genuinely the instructor's, not stale template defaults.

## 4. Notices worth a decision

1. **The download-name prefix is stripped on three tabs and not on two others** (see 1.5).
2. **The public Assignments tab's note is unreachable** (see 2.1).
3. **The assignment page's `Download` block and the Assignments index's `problems (pdf)` /
   `attachments (zip)` links are dead** on generated sites - nothing writes the front matter
   they read (see 1.4).
4. **`Teaching Assistants` renders on the public site over a permanently empty list.**
5. **An unrecognised `type:` in `schedule.yml` renders a colourless row labelled with the raw
   type.** Deliberate - it keeps the site up instead of failing the build - but the row is
   visibly odd and nothing warns anybody.

## 5. NOT editable here

Only the generic chrome, from `dsl-jekyll-theme` pinned at its v2.0.0 commit: the site
header and footer, how the nav bar renders the `_data/nav.yml` rows, the brand colours and
display font, and the `default` / `page` / `post` layouts. `_sass/_course.scss` ships from
here but is imported LAST by the theme's own stylesheet, so it can override any of the
above. A change to the theme itself needs a PR to that repo and a bump of `THEME_REF` in
`site_repo.py` - which is what pins six live sites to one known-good commit rather than to
a moving `main`.

*(Its exact footer and header wording is not quoted here: that repo is not in this
worktree, so it would be a guess rather than a render.)*
